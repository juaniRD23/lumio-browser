## Your work, in order
### 1. security
Build: (1) HTTPS-First mode (Settings › Security › 'Always use secure connections', off by default; when on, upgrade http:// navigations to https:// and fall back with a warning interstitial 'Connection is not secure — Continue to site' if HTTPS fails; never for localhost/intranet hosts/IPs). (2) Secure DNS: Settings 'Use secure DNS' with providers (OS default / Cloudflare / Google / Quad9 / custom DoH URL) via app.configureHostResolver({secureDnsMode, secureDnsServers}) applied at startup and on change. (3) Safe Browsing equivalent: periodically fetch open phishing/malware URL blocklists (e.g. URLhaus host list, OpenPhish feed — check their licenses/allowed use and pick ones that allow it; store locally, refresh daily, never send the user's URLs anywhere), block navigations to listed hosts with a red 'Dangerous site' interstitial (Back to safety / details / proceed only via 'visit this unsafe site' link), and warn on dangerous downloads (executables from listed hosts, double extensions like .pdf.exe, and 'insecure download' for http downloads on https pages: Keep / Discard in the downloads bubble). Setting: Standard protection on by default; No protection option. (4) Manage certificates (Settings › Security: open the macOS certificate manager, Keychain Access) and client certificates: app 'select-client-certificate' shows a chooser dialog listing certificates (subject, issuer, valid until) with OK/Cancel and remembers per host for the session. Reuse the cert-details viewer from the launch-blockers batch if present on this branch; otherwise build a small one in a separate module. (5) Password Checkup: check saved passwords against Have I Been Pwned's k-anonymity range API (only the first 5 SHA-1 hex chars leave the device) on demand from the Passwords page ('Check passwords') and show compromised/reused/weak counts and per-entry warnings; a 'Safety check' section in Settings that runs: updates, passwords, safe browsing on/off, extensions, and shows results. (6) Lookalike/IDN protection: show punycode in the omnibox for mixed-script or confusable hostnames (Chrome's basic rules: mixed scripts, whole-script confusables with Latin) and a 'Did you mean <site>?' interstitial for close lookalikes of top sites you visit; insecure form submission warning (https page submitting a form to http: 'The information you're about to submit is not secure' [Send anyway] [Go back]). (7) Device choosers: select-usb-device, select-hid-device, select-serial-port, select-bluetooth-device: a chooser dialog listing devices with Connect/Cancel; File System Access (showOpenFilePicker/showSaveFilePicker/showDirectoryPicker) permission prompts ('Let site edit files?'). (8) Privacy extras: built-in ad & tracker blocking (Settings › Privacy 'Block ads and trackers' — choose the default and explain; use a maintained filter-list engine such as @ghostery/adblocker-electron only if it fits the build (justify) or a minimal tracker-domain blocklist via session.webRequest), 'Send a Do Not Track request' and Global Privacy Control headers, WebRTC IP handling policy (default_public_interface_only via webContents.setWebRTCIPHandlingPolicy), and auto-revoke permissions of sites not visited for 90 days (Chrome's 'Review unused site permissions'). (9) Capture indicators: a red recording dot on tabs using camera/mic/screen capture (find Electron's signal, e.g. session 'media-access' / permission checks of active streams + desktopCapturer usage in the existing screen-share picker), a 'Sharing this tab' bar with [Stop sharing], and sharing a single browser tab (with its audio) from the existing screen-share picker.
Commit + push after each finished sub-item.
